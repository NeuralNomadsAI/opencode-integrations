# integration-kit

Shared core of the integration plugins. Each plugin bundles it into its build, so two integrations loaded in the same OpenCode daemon cannot diverge. It is not published to npm.

| Module                       | Role                                                                                                                                                                                                                                                    |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `types.ts`                   | Method manifest types (`methods/**.json`)                                                                                                                                                                                                               |
| `method-registry.ts`         | Loads the manifests of a plugin, sorted by name                                                                                                                                                                                                         |
| `manifest-args.ts`           | Validates and normalizes tool arguments against a manifest                                                                                                                                                                                              |
| `plugin-tools.ts`            | Builds OpenCode V2 tools (`@opencode/plugin` 2.2) from manifests and registers them under the integration's namespace, honoring cancellation; executors return text or content parts (`ToolContent`, for attachments)                                   |
| `coherence-check.ts`         | Checks manifests, handlers and the tools mentioned by skills against each other                                                                                                                                                                         |
| `marker.ts`                  | Marker types, the draft specification integer and ID helpers                                                                                                                                                                                            |
| `contract.ts`                | RPC status contract 1: constants (lease, bounds), types, wire schemas equal to `spec/schemas/rpc.schema.json` (`rpcDefinition` registers them without `pattern`, which OpenCode 2.2.5 refuses), `advertise`/`withdraw` input validation, display bounds |
| `integration-rpc.ts`         | `createIntegrationRpc`: handlers for `ctx.rpc.register`, `status` assembly, bounded `installHost`, payload-free event relay and lease sweeping                                                                                                          |
| `offer-registry.ts`          | Offer registry with injectable clock and hello transport; `sharedOfferRegistry` keeps it on `globalThis[Symbol.for("neuralnomads.<app>.offers")]`; `liveHellos()` also gives each live host's method table                                              |
| `host-client.ts`             | Loopback client of host wire protocol 1 (127.0.0.1 only, bounded, cancellable; errors never carry the endpoint, `HostError.detail` keeps the host's bounded explanation)                                                                                |
| `hello.ts`                   | `hello` validation, canonical JSON and capability hash, compatibility with the marker's `host` block                                                                                                                                                    |
| `host-state.ts`              | Normative derivation of `status.host.state`, WSL detection                                                                                                                                                                                              |
| `validators.ts`, `output.ts` | Small JSON helpers                                                                                                                                                                                                                                      |
| `python/opencode_service.py` | Reference discovery client of headless hosts (standard library only): service registrations, the `global.config` Location with the `OPENCODE_CONFIG_DIR` fallback setting, `service-<name>` targeting, capability hash. Host parts vendor it.           |

Skill loading lives in the Blender pilot (`integrations/blender/plugin/src/skills.ts`) until a second integration needs it.

The tests of the Python client run the system Python (`python3`, or `python` on Windows; `PYTHON` overrides it) against fake OpenCode services; every path comes from the test's own HOME and XDG folders.

## Origin of the modules

The kit reconciles the two OpenCode V2 migrations of the previous runtime, reviewed file by file:

| Module                                                                 | Taken from                          | Notes                                                                                                                                                                                                                                                                                                                                      |
| ---------------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `plugin-tools.ts`                                                      | Verified V2 port (the M365 variant) | The only variant built on `@opencode/plugin` V2 `ToolEditor`/`Info`: namespaced tools, argument validation before execution, abort checks. The other variants still targeted the V1 `tool()` helper or a hand-written schema type. Checked against the 2.2.5 type definitions.                                                             |
| `manifest-args.ts`, `method-registry.ts`, `validators.ts`, `output.ts` | Shared runtime                      | Identical in every copy apart from line endings.                                                                                                                                                                                                                                                                                           |
| `coherence-check.ts`                                                   | Shared runtime                      | Unused import removed; `bundleName` renamed `integration`.                                                                                                                                                                                                                                                                                 |
| `types.ts`                                                             | Shared runtime                      | Bridge transport types removed with the host dispatcher; `requires.bridgeMethods` renamed `hostMethods`; `dangerous` flag added.                                                                                                                                                                                                           |
| host dispatcher                                                        | Not taken                           | It inlined Python scripts from the npm package and sent them to the host's code-execution primitive, which the specification forbids: `native` hosts expose a fixed method table and never import code from the package. Its V2 cancellation fix lives on in `plugin-tools.ts`: executors receive the tool context and its abort `signal`. |
